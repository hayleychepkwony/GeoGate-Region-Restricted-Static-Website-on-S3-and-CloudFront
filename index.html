Follow a request

Choose a visitor and see what happens to their request.

  1. The browser asks for the page

    The request goes over HTTPS to the nearest CloudFront edge location.

  2. Country check

    CloudFront works out the visitor's country from their IP address. It is not on the block list, so the request continues.

  3. Cache lookup

    If the edge already holds a fresh copy it answers straight away. If not, it fetches the file from S3.

  4. Private bucket

    S3 only answers requests signed by this exact CloudFront distribution. The bucket is never public.

The stack

Four pieces, each with one clear job.

Amazon S3

Stores index.html, error.html and style.css. Block Public Access is on, so the only way in is through CloudFront.

Amazon CloudFront

Caches the site at edge locations worldwide, redirects HTTP to HTTPS, and serves every visitor from a nearby location.

Origin Access Control

CloudFront signs each request to S3. A bucket policy then allows reads only when the request comes from this distribution.

Geographic restriction

A country block list built into CloudFront. It runs before the cache and the origin, and it needs no extra firewall service.

Build notes

Things worth remembering from setting this up.

Why not use S3 static website hosting directly?

That mode needs a public bucket, serves plain HTTP only, and cannot filter by country. A private bucket with Origin Access Control fixes all three.

Why did the plain address say “Access Denied” at first?

CloudFront had no default root object. Asking for / made S3 look for a file with an empty name. Setting the default root object to index.html fixed it.

How accurate is the country check?

CloudFront infers the country from the visitor's IP address using a third-party database. It is very good but not perfect, and a VPN changes the answer, which is exactly how the block was tested.
